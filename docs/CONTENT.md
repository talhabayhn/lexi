# Lexi — content model & pipeline

## 1. Pipeline
```
content/cards/<level>/*.csv           ──┐
content/categories.csv, meta.json,      ├─▶ tools:content-compiler (JVM) ──▶ validate ──▶ content.db + content-version.txt
content/blocklist.txt                   │                                  (bundled as shared's Compose resources files/)
<external packs dir> (optional)       ──┘
```
- Source of truth = CSV in git (reviewable diffs). `content.db` is a build output: **gitignored**, regenerated by
  every build (locally, in CI and in the Xcode build); never edit it by hand.
- Build wiring (ADR 0018): `:tools:content-compiler:generateContentDb` writes `files/content.db` and
  `files/content-version.txt` under `tools/content-compiler/build/generated/content-db/`; `shared` merges that
  directory into its Compose resources, so every app build bundles the current content and a validation error fails
  the build. The app copies the DB to app storage when the bundled `contentVersion` differs from the installed one
  (`ARCHITECTURE.md` §6).
- `content/meta.json`: `contentVersion` (integer, bump on every content change, or installed apps keep their old
  copy) and `shippedLevels` (levels whose content is release-ready; only these get the hard coverage check of §3 —
  all six before v1.0 release).
- Production flow: open word lists → AI drafts Turkish clues/examples → **human review** (product owner) →
  CSV → compiler validation → playtest.
- **Other clue languages (ADR 0022, after v1.0):** `content/clues/<lang>/*.csv` keyed by card `id` (clue, example
  translation) → AI draft from the English answer + example (not from the Turkish clue) → **native-speaker review**
  per batch (same clue rules as §2) → compiler validates per language (coverage, length, answer leak, blocklist).
  A language ships only when its coverage check passes for every shipped level.
- **Exam packs live in `content/exam-packs/`** (owner decision 2026-10, replaces the earlier private-repo plan; the
  repo goes private before release). The compiler and the app build (`generateContentDb`) read them by default;
  `--packs <dir>` or env `LEXI_PACKS_DIR` override it (the flag wins; `--packs none` compiles without packs). Format,
  validation and owner decisions: `docs/content/EXAM_PACKS.md`. `content/exam_packs/` (underscore) stays gitignored. Without
  packs the compiler still writes a valid `content.db` with empty `exam_pack*` tables. Test fixtures under
  `tools/content-compiler/src/test/resources/fixtures/` are synthetic.

Run by hand for the report (from the repo root; exit 0 = written, 1 = validation errors and nothing written,
2 = usage/I-O error):
```bash
./gradlew :tools:content-compiler:run                                   # content/ + content/exam-packs → build/content/content.db
./gradlew :tools:content-compiler:run --args="--packs none"             # without packs
LEXI_PACKS_DIR=../other-packs ./gradlew :tools:content-compiler:run     # another pack directory, via env
# options: --content <dir> (default content), --out <file> (default build/content/content.db),
#          --tmp <dir> (default build/content-compiler; the DB is built there, then moved atomically),
#          --version-file <file> (also write contentVersion as text), --help
SOURCE_DATE_EPOCH=1700000000 ./gradlew :tools:content-compiler:run     # sets meta.builtAt (reproducible)
./gradlew :tools:content-compiler:generateContentDb                     # what the app build runs
```
Output is reproducible: the same input gives a byte-identical `content.db`. `meta.builtAt` is written only when
`SOURCE_DATE_EPOCH` is set (release/CI builds); `meta.contentVersion` is always there.
The report lists cards per level × letter (`!` = below the minimum), cards per category × level, exam packs,
then warnings (stdout) and errors (stderr) as clickable `file:line: error: message`.

### Exam pack directory layout (`content/exam-packs/`)
```
packs.csv               id,name,description,is_pro,sort        (id = slug, is_pro 0/1)
units/<pack-id>.csv     card_id,unit                           (references any card id; unit may be empty)
cards/<LEVEL>/*.csv     optional pack-only cards, same schema and rules as §2
```
Pack-only cards are validated like level cards (unique id/answer per level) but excluded from level coverage.
Owner decision: they are excluded from free level wheels too. They are written with `card.pack_only = 1`; every
level-wheel/category query must filter `pack_only = 0`, and they are reachable only through `exam_pack_card`.

- A word that exists anywhere (base or another pack) is referenced by id in `units/<pack>.csv`, never re-created.
  Every pack has ≥ 5 cards per letter.
- `packs-meta.csv` holds title_tr/title_en, level range, card target and free preview letters (compiled and
  validated into `content.db` `exam_pack` / `exam_pack_card` tables). Rules and owner decisions:
  `docs/content/EXAM_PACKS.md`; review notes: `docs/content-review/EXAM-*-summary.md`; compiler numbers per pack:
  `docs/content-review/EXAM-PACKS-qa.md`.
- QA without Gradle: `python3 tools/content-qa/qa.py` (charset, letter rule, leaks, duplicates, per-pack letters).
- Pack answers count in the per-level example leak check: a new base example must not contain a pack answer of
  its level either (the compiler reports it like any other leak).

## 2. Card CSV schema (`content/cards/<level>/*.csv`, UTF-8, comma, header row; any file name, e.g. one file per category)
| column | type | rule |
|---|---|---|
| `id` | slug | unique forever, `<level>-<answer>[-n]`, e.g. `a1-kitchen`. Never reuse or rename. |
| `answer` | text | English, uppercase A–Z and single spaces only (`GIVE UP`). Length 2–14 letters. |
| `letter` | A–Z | wheel letter this card serves |
| `rule` | `STARTS`/`CONTAINS` | `STARTS` ⇒ answer starts with `letter`; `CONTAINS` ⇒ answer contains it (not as first letter) |
| `pos` | `noun`/`verb`/`adj`/`adv`/`phrase`/`idiom`/`phrasal` | shown as "İPUCU · İSİM" |
| `clue_tr` | text | Turkish clue. A1–B1: direct translation ("mutfak"). B2+: short Turkish definition or translation + context. ≤ 60 chars. Must not contain the answer. |
| `example_en` | text | natural sentence containing the answer (used blanked for the Example joker) |
| `example_tr` | text | translation of the example |
| `difficulty` | 1–5 | within the level |
| `tags` | `a|b` | optional (e.g. `false-friend`, `exam:lgs`) |
| `category` | category id | must exist in `content/categories.csv` (§4) |

Level comes from the folder name (`A1`, `A2`, `B1`, `B2`, `C1`, `NAT`). See `content/cards/A1/sample.csv`. Clues for other languages (v2) go in `content/clues/<lang>/…` keyed by `id`.

### Clue & example rules (owner review, apply to every batch)
- **No other answer in examples:** `example_en` must not contain any other answer of the same level as a whole
  word (all files incl. `sample.csv`), or the Example joker leaks it. Re-check old examples when adding answers.
- **Ambiguous words:** the clue shows the meaning or usage in natural Turkish ("tek bir diş", "bir sonraki"),
  never a bracket tag like "(tekil)".
- **Near-synonym pairs** (HOUSE/HOME, …) get clearly different clues ("konut, ev binası" vs "yuva, insanın
  yaşadığı yer"); a clue must not fit a near-synonym that is or may become a card on the same letter.
- **CEFR level** follows the official A1–C1 level of the word (Cambridge/Oxford level labels, used only as a
  reference, see §6). Exceptions only for hard-letter coverage (X, Z, Q, …) and noted in the review sheet.
- **`pos` matches the example's usage** (TODAY `adv` ⇒ "I am busy today.", not "Today is …").
- If the Turkish translation is the answer itself (PIZZA), use a short description instead.

## 3. Validation (compiler fails the build on any error)
- unique `id`; answer charset & length; rule consistency with `letter`; clue doesn't contain the answer (case/
  diacritic-insensitive); example contains the answer; no duplicate answer within a level;
- coverage: each shipped level has ≥ ⚙3 cards for every letter it plays (warn < 5); mixed wheel always fills 26;
- profanity/blocklist check; trailing spaces; Turkish characters valid UTF-8.

How the compiler applies them (`tools/content-compiler`, every error is `file:line`):
- Files: strict UTF-8 (a BOM is allowed in every file), RFC 4180 CSV; header must have exactly the schema columns
  (any order); every row the same width; no leading/trailing whitespace, line breaks, tabs/control chars or
  double-encoded UTF-8 (Latin-1 or cp1252 mojibake such as `Ä±` for `ı`, `ÅŸ` for `ş`) in any value.
- `id`: lowercase slug starting with `<level>-` (error); not `<level>-<answer>[-n]` is a warning (ids never change
  when an answer is corrected). Unique across all levels and packs.
- `answer`/`letter`/`rule`: the same `AnswerRules` and `LetterRule` as the app (`core:domain`).
- Clue leak: answers with ≥ 4 letters must not start any clue word (`zebra` → `Zebralar` fails); shorter answers
  must not appear as a whole word (`GO` vs `gol` is fine). Example: must contain the answer as whole words,
  case-insensitive, exactly as written (the Example joker blanks it).
- Example leak: per level (base and exam-pack cards of that level together), `example_en` must not contain any
  other card's answer as whole word(s) (case/diacritic-insensitive, multi-word answers as a phrase; `meet` in
  `meeting` is fine, the card's own answer is ignored). Error is reported at the leaking card and names the
  leaked answer and its card id. Answers of other levels are not checked.
- Columns: `clue_tr` 1–60 chars, `example_en`/`example_tr` non-empty, `pos` from §2 (lowercase), `difficulty` 1–5,
  tags `a|b` (lowercase slug, `:` allowed), `category` exists and is not `mixed`; a category not listed for the
  card's level is a warning.
- Coverage (base content only): shipped level (meta `shippedLevels`) letter < 3 cards → error, < 5 → warning;
  unshipped levels with cards only warn. 3 cards per letter also guarantees the mixed wheel fills 26.
- Blocklist: `content/blocklist.txt`, `[en]` terms checked in `answer`/`example_en` (whole word, case/diacritic-
  insensitive), `[tr]` in `clue_tr`/`example_tr` (whole word, Turkish case folding `İ`→`i`/`I`→`ı`, diacritics
  kept: `sik` does not flag `sık` or `şık`).
- `categories.csv`: unique slug ids, names non-empty, known levels, integer `sort`, `is_pro` 0/1, `mixed` present.

### Smoke sets (dev data)
`content/cards/<A2|B1|B2|C1|NAT>/smoke.csv`: exactly 26 cards (one per letter), every card has `tags = smoke`. They
exist so every level is playable during development; they are not release content. Levels listed in `meta.json`
`smokeLevels` are reported with the SMOKE status. Never ship a level that is only smoke: before a level enters
`shippedLevels`, replace or extend its smoke set with real content (smoke cards may be kept if they pass review).
Known exception: `nat-quite-a-few` covers Q with a multi-word STARTS phrase (no single-word Q idiom fits NAT smoke); `nat-nip-it-in-the-bud` replaced `nat-no-brainer` (owner decision: NO BRAINER is B2, now `b2-no-brainer` in `content/cards/B2/idioms.csv`); multi-word answers carry no hyphens because the answer charset is A–Z and spaces only.

## 7. Database schema (content.db)
Source of truth: `core/data/src/commonMain/sqldelight-content/dev/talhabayhan/lexi/content/db/ContentSchema.sq`
(shared with the compiler, see `ARCHITECTURE.md` §6). Summary:
```sql
CREATE TABLE meta(key TEXT NOT NULL PRIMARY KEY, value TEXT NOT NULL);  -- contentVersion, builtAt (optional)
CREATE TABLE category(id TEXT NOT NULL PRIMARY KEY, name_tr TEXT NOT NULL, name_en TEXT NOT NULL,
  levels TEXT NOT NULL,                     -- 'A1|A2' as in categories.csv
  sort INTEGER NOT NULL, is_pro INTEGER NOT NULL DEFAULT 0);
CREATE TABLE card(
  id TEXT NOT NULL PRIMARY KEY, level TEXT NOT NULL, category_id TEXT NOT NULL REFERENCES category(id),
  answer TEXT NOT NULL, letter TEXT NOT NULL, rule TEXT NOT NULL, pos TEXT NOT NULL,
  example_en TEXT NOT NULL, difficulty INTEGER NOT NULL, tags TEXT NOT NULL DEFAULT '',  -- tags 'a|b'
  pack_only INTEGER NOT NULL DEFAULT 0      -- 1 = exam-pack extra card; level wheel queries filter pack_only = 0
);
CREATE TABLE clue(card_id TEXT NOT NULL REFERENCES card(id), lang TEXT NOT NULL, clue TEXT NOT NULL,
  example_translation TEXT, PRIMARY KEY(card_id, lang));
CREATE TABLE exam_pack(id TEXT NOT NULL PRIMARY KEY, name TEXT NOT NULL, description TEXT NOT NULL DEFAULT '',
  is_pro INTEGER NOT NULL DEFAULT 1, sort INTEGER NOT NULL);
CREATE TABLE exam_pack_card(pack_id TEXT NOT NULL REFERENCES exam_pack(id), card_id TEXT NOT NULL REFERENCES card(id),
  unit TEXT, PRIMARY KEY(pack_id, card_id));
CREATE INDEX card_level_letter ON card(level, letter);
CREATE INDEX card_level_category ON card(level, category_id);
```

## 8. user.db (schema v3)
Source of truth: `core/data/src/commonMain/sqldelight/dev/talhabayhan/lexi/core/data/user/db/*.sq`. Summary:
```sql
progress(card_id TEXT PK, box INTEGER NULL,           -- NULL = not in the notebook; Leitner 0-4 (GAME_RULES.md §10)
  due_epoch_day INTEGER NULL, seen, correct, wrong, last_seen_ms INTEGER NULL, mastered 0/1)
session(id INTEGER PK AUTOINCREMENT, mode, level, category NULL, seed, started_ms, ended_ms,
  epoch_day,                                          -- player's time zone, for stats and streak
  score, correct, wrong, passed, completed 0/1)       -- never written for hot-seat duel (srsExcludedModes)
daily_result(epoch_day, level, score, time_ms, share_code NULL, PK(epoch_day, level))   -- one scored Daily attempt per day per level
streak(epoch_day PK)                                  -- days with ≥ 1 completed wheel, written with the session
joker(type PK, count ≥ 0)                             -- JokerType name → inventory
joker_grant(kind PK, epoch_day)                       -- v2: JokerGrantReason name → last gift day (GAME_RULES.md §7)
```
- Card ids are content slugs; progress of cards that left `content.db` is kept and hidden by the repository.
- Changes only through `<from-version>.sqm` migrations in `core/data/src/commonMain/sqldelight/migrations/` plus a
  frozen snapshot `core/data/src/jvmTest/resources/user-db/<version>.sql` (`UserDatabaseMigrationTest`, ADR 0018).
- v2 (`1.sqm`): `joker_grant` for the daily gift and streak bonus, written with the inventory in one transaction.
- v3 (`2.sqm`): `daily_result` composite PK `(epoch_day, level)` for one attempt per day per level.
- Later, when their features land: Pro refill bookkeeping (M7, a `joker_grant` kind), `achievement(id PK,
  unlocked_ms)` (v1.2), the share-card payload format (M6).
