## Blocker

1. **Daily is now "one attempt per day per level", which reverses an owner decision.**
   `GAME_RULES.md:76` still says "one scored attempt per day (owner decision: per day, not per level)". Commit
   `411b026` changed the schema (`DailyResult.sq` PK `(epoch_day, level)`, `migrations/2.sqm`), the repository
   (`UserRepositories.kt:154-190`), the domain contract (`core/domain/.../repository/UserRepositories.kt:50-65`),
   `GetDailyWheel.kt:24` and the tests to per level, and rewrote `CONTENT.md` §8 to match. GAME_RULES was not
   touched and no owner sign-off is recorded, so the rules and the code now disagree on a product rule
   (CLAUDE.md: product behaviour changes need the owner).
   *Fix:* ask the owner. If "per day" stands, put the PK back to `epoch_day` with a `3.sqm` migration (the v3
   table can hold several rows per day, so the migration has to pick one, e.g. the earliest; add a snapshot
   `4.sql` and a test for it), and make `get`/`record` per day. If "per level" is the new decision, update
   GAME_RULES §5 in the same commit.

## Major

2. **A daily that crosses midnight is saved under the wrong day.** The wheel and seed come from the start day
   (`GetDailyWheel.kt:24-29`), but `FinishGame` records the daily under the day the game *ended*
   (`FinishGame.kt:61` → `epochDay = clock.epochDay(endedAtMs)`, line 84). If you start at 23:58 and finish at
   00:01, day D+1's daily shows as played even though you never saw that wheel, and day D's stays open.
   *Fix:* carry the daily `epochDay` (or the seed) in the game route or the SavedGame and record with that. Add a
   regression test with `FakeAppClock` set across midnight.

3. **Daily can silently fall back to a random, non-shared wheel.** `GameViewModel.kt:81` takes
   `getDailyWheel: GetDailyWheel? = null` and `GameModule.kt:40` passes `getOrNull()`. If the binding is missing,
   `GameViewModel.kt:322` skips the daily branch and builds a wheel from `seeds.nextSeed()`. That breaks "everyone
   gets the same wheel" and also skips the already-played check. `FinishGame.kt:31` has the same nullable default
   (`daily = null`), and if it is null no daily result is ever saved.
   *Fix:* make both required (non-null, `get()`), and fail loudly for DAILY when missing.

4. **The daily branch in GameViewModel has no tests.** `GameViewModelTest.kt` uses `GameMode.DAILY` but never
   passes a `GetDailyWheel`, so the tests run the random-seed fallback (item 3). Nothing checks that a daily game
   uses `DailySeed`, that `AlreadyPlayed` sends `GameEffect.Abandoned`, or that `NoCards` shows the error.
   *Fix:* add ViewModel tests for Ready / AlreadyPlayed / NoCards using `FakeDailyRepository`.

5. **The home streak badge is stale after a day change (regression).** Before this change the combine used the
   combined `day` (`Stats.currentStreak(days, day)`). Now `GetStreakStatus.observe()`
   (`StreakStatus.kt:32-40`) reads `clock` only when the streak table emits. `HomeIntent.Resumed`
   (`HomeViewModel.kt:91`) updates `today`, but the combine (`HomeViewModel.kt:45`) reuses the last
   `StreakStatus`, which was computed on the old day. Example: the app is open from yesterday, the user missed a
   day, and the badge still shows the old streak until the table changes.
   *Fix:* compute the streak from `today` inside the combine (`Stats.currentStreak(streak.days, day)`), or give
   `GetStreakStatus.observe(today: Flow<Long>)`. Add a test that advances the clock and sends `Resumed`.

6. **The daily seed does not follow ARCHITECTURE §4, and there are two seed functions that disagree.**
   ARCHITECTURE.md:112 says `Seeds.stableHash("daily:" + yyyy-MM-dd + ":" + level + ":" + contentVersion)`.
   `DailySeed.kt:20-22` (the overload the app uses) builds `"daily:<epochDay>:..."` and wraps it in `mix64`.
   The `CivilDate` overload (`DailySeed.kt:26-32`) uses `yyyy-MM-dd`, so it returns a *different* seed for the
   same day. Once seeds are shared (challenge links, share codes, the v1.1 server), this causes cross-client
   mismatches.
   *Fix:* pick one key format, delete the other overload, update ARCHITECTURE/GAME_RULES §13, and pin a literal
   seed value in a test (see 7).

7. **The "golden" tests do not pin anything.** `DailySeedTest.kt:50` ("golden daily seed values are pinned")
   compares `seed(x)` with `seed(x)`, which can never fail. `DailyWheelGoldenTest.kt:67` checks only that
   slot letters are A–Z in order, not which cards were picked. A change to the seed or generator would pass both.
   *Fix:* assert literal `Long` seeds and the exact list of card ids for a fixed day, level and version, like
   `GoldenSnapshots.kt`.

8. **Exam-pack content is now committed to the repo, reversing an earlier owner decision. Please confirm.**
   Before this period, CONTENT.md §1 and ROADMAP M7 said "pack content lives in a separate private repo, never in
   this one". `828bbd4`/`7a167c3` add `content/exam-packs/` (including Pro `yds-yokdil`), make it the default
   pack dir (`tools/content-compiler/build.gradle.kts:57-59`, `Main.kt` `DEFAULT_PACKS`), and rewrite the docs
   as "owner decision 2026-10 … the repo goes private before release". I cannot verify that decision from the
   repo. If the repo is public now, the paid content is already published.
   *Fix:* the owner should confirm the decision and the repo's visibility. If it is not confirmed, move the
   content out and restore the gitignore. History rewrite is the owner's call.

9. **The daily-card states were built without a design.** `docs/design/screen-map.md:42` lists "Daily wheel
   intro / already-played state" as M6 design debt. `HomeScreen.kt:241-272` adds AlreadyPlayed and Unavailable
   variants (new copy, no chevron, disabled), and `screen-map.md` was not updated to say they were built without
   a design. CLAUDE.md rule 3 says to stop and ask, or build from `16-components` and flag it as "needs design".
   *Fix:* mark these states as DESIGN-DEBT/"needs design" in screen-map, and get them designed.

## Minor

10. **Dead or duplicated domain code.** `RecordDailyResult` (`RecordDailyResult.kt`) is bound in
    `AppModules.kt:42` but never used; `FinishGame.kt:58-68` does the same job inline. `StreakSemantics`
    (`StreakStatus.kt:11-19`) is used only by tests. `DailyRepository.observe(epochDay)` / `observeDay` have no
    production callers (`UserRepositories.kt:56-59`). `GetStreakStatus.current()` repeats `observe()`.
    *Fix:* delete them, or have FinishGame use `RecordDailyResult`.
11. **User-facing Turkish string in `core:domain`.** `StreakStatus.kt:16`
    `comboBadgeText = "×$streak SERİ"` breaks rule 5 (strings belong in resources, TR and EN) and the purity of
    the domain module. *Fix:* delete it (the game UI already owns the combo badge).
12. **The home daily state is not reactive to the level and is hard-coded in navigation.** `HomeViewModel.kt:68,72`
    reads `mutableState.value.playLevel` once per day, and `LexiNavHost.kt:80` always opens
    `GameRoute(Level.A1, GameMode.DAILY)`. Once playLevel is persisted (TODO M5), the card and the game will
    disagree. *Fix:* pass the level in the `NavigateToDaily` effect and observe the level as a flow.
13. **`.catch { emit(Unavailable) }` ends the daily-card flow for the rest of the ViewModel's life**
    (`HomeViewModel.kt:80`). A temporary DB error, or a `today` change afterwards, never recovers it.
    *Fix:* catch inside `flatMapLatest` per day, or use `retryWhen`.
14. **`DailyResult.timeMs` is wall-clock time and includes pauses** (`FinishGame.kt:64`
    `endedAtMs - startedAtMs`), so it is not the play time a share card or leaderboard would compare.
    *Fix:* take the elapsed time from the engine state or summary.
15. **The home screen builds the whole wheel just to set the card state.** `HomeViewModel.kt:72` calls
    `getDailyWheel` each time `daily.observe` emits. It is cheap today, but it is wasted work on the main
    flow. *Fix:* add a cheap `hasPlayableCards(level)` query, or cache per day.
16. **`!!` in the content compiler** (`ContentCompiler.kt:354` `parseFlag(packRow["is_pro"])!!`). This breaks
    the "No `!!`" rule in CONVENTIONS. *Fix:* keep the parsed value from the validation pass.
17. **CONTENT.md is out of date.** `CONTENT.md:64` says `packs-meta.csv` is "not read by the compiler yet", but
    `7a167c3` reads and validates it and writes it to `content.db`.
18. **Several tests mainly check the fakes.** `StreakTest.kt:18,113` ("increments on first completed game",
    "travelling timezones…") set `FakeStreakRepository.days` by hand and then check `Stats.currentStreak`. The
    code that writes the streak day (`SessionRepository.record`) and the time-zone handling are never run. The
    timezone test only shows that `FakeAppClock` handles offsets. *Fix:* drive these through
    `FinishGame` + `FakeSessionRepository`, or delete them as duplicates of the `Stats` tests.
